## Последние изменения (06.10.2026)
- **Этап 5.9 «Доработки» — выполнен (06.10.2026), сверен на устройстве Олегом («Всё ок»).**
  - 5.9.1 `TimeoutHttpClient` (lib/services/timeout_http_client.dart) — общий http-клиент с таймаутами; устранено «вечное зависание» сети. В main.dart — глобальный `rootScaffoldMessengerKey` (SnackBar поверх диалогов).
  - 5.9.2 Свайп влево в списке поставщиков → bottom sheet «Архивировать / Удалить»; каскадное удаление (порядок с учётом `readings.channel_id ON DELETE RESTRICT`: readings → receipts+Storage → payments → channels → supplier); `deletionImpact`; исправлен баг архивации (нужен `await`, был fire-and-forget).
  - 5.9.3 **Колонка «Расход»** в Excel: экран ввода показаний теперь передаёт `consumption` (Σ current−previous) в `PaymentRepository.create`; для старых платежей (`consumption=null`, но есть `reading_snapshot`) отчёт восстанавливает расход из снимка (`_consumptionFromSnapshot`).
  - 5.9.4 Заливка зелёным — **только ячейка «Статус»** (не вся строка). Добавлена колонка **«Адрес»** (2-я, после «Поставщик»). Причина пустого адреса: `_supplierFromRow` в reports_screen и payment_screen не копировал `address` — исправлено.
  - 5.9.5 **Автофильтр** в Excel: пакет `excel ^4.0.6` его не умеет → пост-обработка xlsx (вставка `<autoFilter ref="A1:<col><row>"/>` после `</sheetData>`); прямая зависимость `archive ^3.6.1`; при ошибке — файл без фильтра. Проверено openpyxl (`auto_filter.ref = A1:K4`).
  - 5.9.6 **Формат показаний** без лишнего «.0»: функция `formatReading` (lib/utils/amount_format.dart) — целые без дробной части (45344, 42845), дробные без хвостовых нулей. Применена: карточка платежа (история), экран оплаты (`_readingText`), ввод показаний (предпросмотр/валидатор/производные), Excel (Текущие/Предыдущие/Расход).
- **Баг зависания экрана «Оплата» (был открыт 04.10.2026) — закрыт** таймаут-клиентом 5.9.1.
- 5.7 «Чеки в отчёте на Яндекс.Диске» — папка периода «/Коммуналка/<Месяц>_<Год>», копии xlsx + чеков; ссылка в Excel ведёт на файл на Диске (publish + public_url, откат на клиентскую ссылку); имя чека «Чек_<Поставщик>_<дд.мм.гггг>.<ext>». Коммит `a723e04`.

## Активные решения и компромиссы
- 5.9.3: расход в отчёте — источник правды `payment.consumption`; при null — fallback из `reading_snapshot`. Новые платежи всегда пишут consumption.
- 5.9.5: автофильтр — пост-обработкой zip, т.к. пакет excel не поддерживает; не критично → при ошибке отдаём файл без фильтра.
- 5.7: критерий «закрытия месяца» — наличие платежа (не блокировка).
- 5.7: чеки остаются в Supabase Storage, на Диск — копии; ссылки в Excel — на файлы на Диске (постоянные).
- 5.7: если у токена нет права чтения — откат на клиентскую ссылку; после `cloud_api:disk.read` ссылки ведут на файлы.
- 5.8: подход «вариант A» — сохранены камера/галерея, добавлен выбор PDF.
- 5.14: поля показания (CounterVal) в QR не добавляются — банки их не подставляют.
- 6.1: иконка оставлена стандартной Flutter — замена запланирована на 7.6.
