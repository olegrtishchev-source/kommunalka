# Product Context — Kommunalka

## Проблема
Пользователь ведёт учёт показаний и оплат ЖКУ вручную (Excel + разрозненные квитанции). Нужен единый инструмент: хранение реквизитов, расчёт сумм по показаниям, платёжный QR, чеки, отчёты, облачная синхронизация.

## Целевая аудитория
Один пользователь (личное использование), один Android-смартфон. Без мультипользовательского режима.

## Пользовательские сценарии (ТЗ §8)
1. Добавление поставщика (вручную или скан QR).
2. Ежемесячный ввод показаний/суммы.
3. Оплата (реквизиты + расчётная сумма + QR → банк → факт-сумма → автостатус → чек).
4. Просмотр истории.
5. Закрытие месяца (проверка полноты → Excel-отчёт → Яндекс.Диск).

## Ключевые решения
- **Supabase вместо Firebase**: HTTP-запросы (без VPN), щедрый бесплатный тариф, Postgres.
- **drift поверх Supabase**: у Supabase нет офлайн-кеша.
- **Оплата без банковского API (ТЗ v2.1)**: платёжный QR по ГОСТ Р 56042, загрузка в банк из галереи.
- **Яндекс.Диск для отчётов**: прямой доступ с любого устройства, 10 ГБ, без VPN.
- **Пакет `excel`**: чистый Dart, без лицензий.

## Важные детали
- Статус платежа: pending / partiallyPaid / paid — вычисляется по соотношению факт/расчёт (PaymentStatus.calculate).
- Оплата может отличаться от расчёта — факт-сумма редактируема.
- Чек привязывается к платежу, ссылка кликабельна.
- Передача показаний: приложение не отправляет само, а открывает канал (bank_form / cabinet / email).
